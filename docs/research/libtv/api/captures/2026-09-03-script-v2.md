# 2026-09-03 Script V2 协议捕获与证据边界

## 捕获条件与隐私边界

- 页面：登录态 Workflow 画布中的 Script V2 节点；视口为 Chrome `1440 × 900` CSS 像素。
- 动作：打开脚本节点，经过“剧本生成/角色生成/自己编写”入口，确认镜头、准备资产、合成提示词，并观察节点保存与报价请求。
- 费用边界：没有确认真实生成、没有消耗积分；本仓库只实现 frontend-only local mock。
- 凭证边界：本文不保存 Cookie、Authorization、Access Key、真实账户/空间/项目/节点/任务/资产/请求/trace 标识，也不保存官网私有媒体地址。
- 下方所有远程标识使用 `PROJECT_ID`、`NODE_ID`、`REQUEST_ID`、`SESSION_ID`、`TRACE_ID`、`ASSET_ID`；这些是占位符，不是可用凭证。

## UI 观察（interaction-linked）

| 阶段 | 观察到的行为 | 本地归一化 |
|---|---|---|
| 入口 | 新版脚本提供剧本生成、角色生成、自己编写三条入口；默认语言模型显示为 GVLM 3.1，界面成本为 6。 | `entry` 为 `screenplay`、`character` 或 `manual`，持久化于 `ScriptV2State`。 |
| 镜头 | 全屏三阶段流程的第一阶段编辑镜号、5–15 秒时长、12 种景别、画面、对白、音效、运镜和双轨提示词。 | `rows[]`，`shotNumber` 必须从 1 密集递增；提示词分别为 image/video track。 |
| 资产 | 第二阶段按 character、scene、prop 管理资产；角色可来自 AI、当前画布或本地上传。 | `assets.characters/scenes/props` 三个 role bucket；资产本身不等同于工作流节点。 |
| 提示词 | 第三阶段支持单镜/批量智能或自动合成；批量生图与批量生视频使用各自提示词轨。 | `promptBatchRuns[]` 记录最多 20 镜一批的本地进度与 request context。 |
| 导出 | 可下载含镜头字段和资产表的 CSV；批量生成先经过确认门，再创建普通 Jobs。 | CSV 是前端导出，不是 Script V2 run 的持久化副作用。 |

相关视觉证据见 `docs/research/libtv/pages/canvas/README.md` 的“脚本节点”表和相邻
`screenshots/script-v2-*.png`。

## 观察到的官网请求形状

### `POST /api/canvas/nodes/batch`（shape-confirmed）

```http
POST https://api.liblib.tv/api/canvas/nodes/batch
Content-Type: application/json
```

```json
{
  "projectUuid": "PROJECT_ID",
  "nodes": [{ "id": "NODE_ID", "type": "SCRIPT_NODE" }],
  "connections": [],
  "version": "VERSION",
  "requestId": "REQUEST_ID",
  "sessionId": "SESSION_ID",
  "timestamp": "TIMESTAMP"
}
```

官网 envelope 的字段名被观察为 `code`、`data`、`msg`、`trace_id`；`trace_id` 的值在
研究记录中一律替换为 `TRACE_ID`。官网的节点 data 使用 provider 扩展和 snake/camel
混合字段；本地不直接持久化该 envelope，而是将唯一规范状态写入
`node.data.extra.scriptV2`，再由 Canvas 的 `expectedRevision` mutation 保存。

### 算力报价（shape-confirmed / interaction-linked）

打开或改变 Script V2 生成配置时观察到：

```http
POST https://api.liblib.tv/api/task/generation/power/calculator
```

响应形状为 `ExternalEnvelope<{ power: number }>`，即 `data.power` 是报价字段。该观察只
证明 envelope 形状和 UI 关联，不证明动态价格。frontend-only local mock 通过
`POST /api/script-v2/quotes` 返回带 `priceVersion: "script-v2-local-1"` 的确定性 quote，
不调用该官网地址。

### 生成与重算参数（bundle-confirmed / interaction-linked）

当前客户端构造/消费以下 scene 参数名：

- `script-generate-v2`：以故事文本、入口、模型和可选角色表单生成镜头及资产；
- `script-recompute-prompts-v2`：以最多 20 个目标镜头和最多 100 个上下文镜头重算 image/video 双轨提示词；
- 资产生成沿用图片模型的质量、分辨率和画幅字段。

上述 scene 名和字段来自静态客户端/交互链路，未将它们误记为完整官网响应。脱敏的
重算请求样本见 [`script-v2-official-recompute.sanitized.json`](../../../../api/examples/script-v2-official-recompute.sanitized.json)。

## 结果解析边界（bundle-confirmed）

结果适配器兼容两种观察到的外部载荷：

1. 直接 JSON 结果；
2. JSON 字符串位于 `texts[0]` 的结果。

解析后只进入本地严格的 operation-discriminated result：`generate-full` 返回 title、
rows、assets；`recognize-assets-only` 返回 assets；`recompute-prompts` 返回目标镜头的
双轨提示词；`generate-asset` 返回一个 ready/failed asset。未知 provider 扩展留在证据
adapter 边界，不穿过本地 Zod API 契约。

## 限制与证据等级

| 事实 | 等级 | 结论 |
|---|---|---|
| 三阶段 UI、12 景别、5–15 秒、角色/场景/道具分组 | `interaction-linked` | 固定为本地状态和 UI gate。 |
| `nodes/batch` 顶层字段、报价 `data.power` | `shape-confirmed` | 仅用于 adapter 映射，不复制官网 envelope。 |
| `script-generate-v2`、`script-recompute-prompts-v2`、结果 parser 分支 | `bundle-confirmed` | 记录协议边界；字段仍以本地 Zod schemas 为准。 |
| 真实成功/失败/取消/重试/最终成本 | `COST_GATED` | 由确定性 local mock 场景覆盖，不冒充官网网络事实。 |
| 20 镜单批、100 镜上下文 | `bundle-confirmed` | 本地 recompute request 与 prompt batch state 同步限制。 |

## 本地实现声明

本仓库的 Script V2 API 是 frontend-only local mock：使用固定时钟、稳定 fixture ID、本地
SVG/JSON 和内存/文件 mock 状态；没有真实 LibTV 凭证，没有真实后端调用，没有远端模型
提交。未来后端接入必须在 adapter/transport 层完成认证和 provider 映射，页面组件与
`ScriptV2State`、四个 local API operation 的调用方式保持不变。
