# 会员、积分与订阅流程

## 已观察入口

```text
首页
|- 开通会员 -> 创作会员 / 团队版会员
|  |- 周期切换 -> 档位/积分配额 -> 开通动作
|  `- 团队版：席位数 -> 团队共享月积分 -> 开通动作
`- 会员超市 -> 模型专享积分包
   `- 设置消耗顺序 -> 恢复默认 / 取消 / 应用

登录后头像菜单
|- 积分余额 -> 获取 / 消耗 / 返还明细 -> 筛选 / 下载 / 分页
|- 充值 -> 固定通用积分包 / 自定义积分 -> 会员或支付门槛
|- 设置消耗顺序 -> 四类余额池拖拽 -> 取消 / 应用
|- 订阅与开发票 -> 订阅计划 / 购买记录 -> 订单操作 / 发票
`- 创建团队 -> 团队版会员方案 -> 付费 entitlement
```

未登录状态下可浏览方案、权益、估算表和 FAQ；登录后可继续查看余额批次、三类
账本明细、通用充值商品、订阅和购买记录。本轮没有进入支付确认、下载明细、开票，
也没有创建订单或保存消耗顺序。

## 已观察账本投影

- 钱包首页按会员订阅、通用充值、模型卡和免费积分显示聚合余额。
- “已获取”保存来源、生效时间和到期时间，证明同类余额仍由独立批次组成。
- “已消耗”和“已返还”都以任务 ID 关联生成任务，并保留项目、模型和任务详情维度。
- 获取、消耗、返还分别显示笔数与积分合计；筛选、分页和下载属于查询投影能力。
- 购买记录是订单与发票的入口，列出交易时间、商品、订单号、金额、状态和操作。

这些是可见查询模型，不等于站点已经公开内部账本事务实现。双分录、reservation、
settlement 和 reconciliation 仍属于复刻目标设计。

## 生成前扣费门槛

以下为结合页面规则的复刻设计，不代表 LibTV 已公开内部实现：

1. 鉴权并解析个人/团队 workspace，加载会员 entitlement、并发和余额批次。
2. 按已版本化的用户自定义顺序或平台默认顺序生成 quote。
3. 先核销符合条件的模型赠送生成次数，再按到期时间选择积分批次。
4. 在数据库事务内创建 reservation 和明细，不直接覆盖聚合余额。
5. Job 接受后执行；成功按 provider 实际规则 settlement，未用部分 release。
6. 失败时引用原始 charge 创建返还流水，并在积分明细展示关联原因。

默认积分优先级为免费、模型专享、订阅会员、通用充值；同类内部最早到期优先。
报价必须记录规则版本、价格版本、命中批次和过期时间，避免任务排队期间政策变化。

## 订阅与团队购买

- 创作会员订单绑定档位、周期、月积分配额选择和活动版本。
- 团队订单额外绑定 workspace、席位数、每席位配额和总共享额度。
- 自动续费、变更档位、增减席位、取消和到期必须形成独立 subscription event。
- 权益生效与付款回调采用幂等状态机；前端成功页不能作为开通依据。
- 发票从购买记录发起，Invoice 与 Order 分离，保留抬头、状态和失败原因。

## 必测恢复状态

- quote 过期、价格变化、余额批次在提交前过期。
- 支付回调重复、支付成功但权益写入延迟、订单关闭后迟到回调。
- Job 失败后 2 小时内返还、超时未返还和客服 adjustment。
- 用户修改消耗顺序时已有 reservation，既有任务保持原 quote 规则。
- 团队席位/权限变化与正在运行任务并发发生。
- 发票申请失败、重复申请和订单不可开票。
