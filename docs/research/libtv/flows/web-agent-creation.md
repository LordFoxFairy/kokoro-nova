# Web 与 Agent 创作流程

## 入口

| 步骤 | 行为 | 状态 | 证据/缺口 |
| --- | --- | --- | --- |
| 1 | 从首页自然语言框、快捷 Skill、开始创作或项目内 Agent 进入 | `OBSERVED` | 多入口已截图 |
| 2 | 添加本地/资产库附件 | `OBSERVED` | 附件菜单已截图 |
| 3 | 选择图片/视频模型或保持 Agent 自动选择 | `OBSERVED` | 选择器已截图 |
| 4 | 选择 Skill、收藏项、我的 Skill 或推荐 Skill | `OBSERVED` | 选择器、个性化空态和推荐 Skill 注入均已截图 |
| 5 | 选择手动确认或自动生成 | `OBSERVED` | 自动模式可能消耗积分 |
| 6 | 输入有效目标并提交 | `OBSERVED` | 已执行只读画布分析和一次无写入的 mutation 能力探测；均未生成媒体或修改画布 |

未登录用户在需要私有项目时进入统一登录层；首次登录可能先进入获客问卷。
登录成功后应恢复原始 intent，而不是丢失输入、附件和 Skill 选择。

## 项目与上下文

1. 服务端确定 account、workspace 和 project；没有项目时创建或要求选择，精确
   Web 行为待确认。
2. AgentSession 需要绑定 project，可选绑定当前 canvas；当前只直接观察到画布侧栏，
   是否存在独立 Agent 页以及两者是否共享会话仍待确认。
3. 选中的节点、故事板参考源和视频产物都可作为 context chip 注入。`@` 选择器
   展开后覆盖当前普通组、预设子节点和七个基线节点，并列出模型；即使项目含组与
   示例媒体，placeholder 所称的工作流/资源分组仍未出现。
4. Skill 和模型以版本化引用进入 session，不把整个可变目录复制到消息文本。
5. 附件先登记为 Asset 或安全的 pending upload，Agent 只获得受权限控制的引用。

## ReAct 执行

建议目标状态：

```text
RECEIVED -> PLANNING -> AWAITING_CONFIRMATION -> APPLYING
-> GENERATING -> COMPLETED | PARTIAL_FAILED | FAILED | CANCELLED
```

- GA 理解目标、读取上下文并产出显式 plan。
- 当前手动模式文案只承诺“每次生成前询问”，不能推导所有画布 mutation 或发布
  都有计划审批；Agent 还明确表示通用“计划后暂停等待确认”模式不存在，仅可能在
  信息缺失或不可逆操作时调用 `ask_human`。自动模式仍必须经过权限、合规、额度
  和幂等检查。
- Canvas Mutation Executor 以 `expectedVersion` 应用节点/连线/分组命令；冲突
  时重新读取或请求用户确认，GA 不直接写数据库。
- 每个需要模型执行的节点创建 GenerationJob，AgentRequest 聚合子任务进度。
- 只读调用已观察到素材检索、画布读取、思考中和完成；文本节点创建被 Agent
  明确判定为工具不支持。`ask_human` 的提问、忽略、回答和额度门已实测；手动
  媒体生成确认、生成进度、取消、重试和错误状态仍待采集。

## 已观察的只读 Agent 会话

1. 选择手动模式，输入明确禁止写操作、媒体生成和积分消耗的画布分析请求。
2. 首次提交打开设置确认门；保持自动生成关闭后点击“确认并发送”。
3. 会话先显示素材检索摘要和“思考中”，完成后工具摘要包含未找到素材、找到
   相关素材、读取画布三个阶段。
4. Agent 返回节点表、连线和坐标，但只识别 text/image/video/audio 四个节点；
   Web 画布实际有 7 个节点，导演台、脚本 V2、视频合成未进入工具结果。
5. 完成后自动生成标题，分享和历史入口启用；分享仍需显式生成公开只读链接。
6. 页面刷新可恢复当前消息和回复；新建空会话后可从历史切回原会话。

## 已观察的 mutation 能力边界

1. 新建第二条会话并切到手动模式，提交“创建临时文本节点，但只提出计划、等待
   明确确认”的请求，同时禁止运行模型或消耗积分。
2. Agent 没有展示 plan、确认、拒绝或修改计划控件；处理中便说明当前工具集没有
   `generate_text` 或其他文本节点创建工具。
3. 最终回复明确表示不存在通用“计划-等待-确认”模式；仅在信息缺失或不可逆操作
   时可能使用 `ask_human`，这一路径本轮没有触发。
4. 回复确认没有运行模型或消耗积分；浏览器再次核对工作流仍为 7 节点、1 条边、
   50% 缩放，余额仍为 100。
5. 会话自动标题为“Agent节点创建确认测试”，与第一条会话一同进入历史；测试后
   已恢复自动模式，并确认“自动生成图片/视频”开关仍开启。

## 已观察的 `ask_human` 与额度阻断

1. 第三条会话在手动模式下提交缺少主题、风格、时长、画幅和素材的视频目标，
   同时明确禁止 mutation、模型运行、媒体生成和积分消耗。
2. Agent 进入 `询问中`，渲染专用“询问用户”工具：问题、自由回答、附件、忽略和
   提交。该工具不是普通助手消息。
3. 点击“忽略”后先出现可展开的“询问与选项 / A. 其他”记录；刷新经过头部按钮
   禁用的“请稍候”阶段后，又恢复成原始待回答控件，忽略没有持久化。
4. 回答“停止本次任务”并提交后，界面短暂显示“询问与回答”，随后出现“Agent
   免费体验次数已用光”的全屏个人/团队会员门；没有运行模型或扣除积分。
5. 再次刷新仍恢复成原待回答问题，说明额度校验阻断了工具回答的持久化或确认。
   复刻时应先持久化人类决策，再以同一 tool-call id 幂等续跑或进入额度阻断态。
6. 会话自动标题为“视频制作需求澄清”并进入三条历史列表；它当前仍是服务端
   pending 状态，不能误标为成功完成或已取消。

## 已观察的画布上下文链

```text
工作流文本节点 -> 图片节点 -> 故事板映射
                          -> 查看参考源节点
                          -> 添加到对话
                          -> Agent context chip（未发送）

工具箱预设组 -> 故事板图片/视频产物
                         -> 视频“对话”
                         -> Agent 产物 context chip（未发送）

推荐 Skill -> Agent Skill context chip（未发送）
```

从故事板回切工作流后，文本节点、图片节点和连线仍存在。预设组删除后，三个子节点
与三条依赖边也一并删除。上述行为证明当前 UI 能以共享节点身份跨视图定位，但尚
不能推出 AgentSession、故事板和工作流的数据库结构。

## 结果与恢复

1. Job 产生 Artifact，服务端完成对象存储和元数据写入后才发 terminal event。
2. Artifact 可登记为 Asset，并以节点 output 关联到新的 workflow revision。
3. 会话消息引用 job/node/artifact id；UI 从权威对象加载，不把富媒体只塞进文本。
4. 刷新或 WebSocket 重连使用 event cursor 回放，不能只显示“当前节点”。
5. 重试创建新 attempt，但沿用原 idempotency key/remoteJobId 的恢复规则。
6. 失败需要区分校验、合规、余额、provider、超时、取消和结果持久化失败。
7. `ask_human` 回答/忽略要先落库再启动后续 Agent turn；额度不足不能让刷新后
   回退为同一未回答问题。
8. 同一画布在第二个浏览器打开会驱逐旧编辑会话；旧页面显示阻断层并要求刷新。
   服务端需要显式 editor lease/epoch，避免两个客户端静默覆盖。

## 待采集验收态

- 创建项目过渡；有效输入、首次确认、发送中和完成已观察。
- 手动媒体生成的逐次确认，以及有额度时 `ask_human` 回答后的成功续跑。
- `ask_human` 忽略/回答持久化、额度阻断恢复和重复提交幂等性。
- 已支持 mutation 的工具调用、结果 diff、冲突和撤销；文本节点创建当前不支持。
- 排队、运行进度、预览、取消中、取消完成、失败和重试。
- 部分成功、积分预占/结算/返还、通知中心和声音提示。
- 断网、重复点击、多用户并发修改和 GA 超时；跨浏览器编辑驱逐已观察。
