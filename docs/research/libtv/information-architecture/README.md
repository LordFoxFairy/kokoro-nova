# LibTV 信息架构

## 调研上下文

- 产品形态：公开内容站点 + 登录后 AI 视频创作 Web App + CLI/Agent 接口。
- 主要用户：独立视频创作者、影视/广告团队成员、通过 Agent 或 CLI 自动化的
  技术用户。
- 核心任务：发现创作方法、从提示词/Skill 启动项目、在画布组织多模态素材、
  生成和编辑视频、发布或复用作品。
- 硬约束：个人/团队资源隔离、积分与会员额度、人像合规、公开/私有权限、
  长任务恢复以及中文为主的标签体系。

## IA 结论

用户主要围绕 workspace 中的项目、画布、节点和资产组织创作，因此采用
**对象优先**的信息架构；Agent、Skill 和模型是项目内的创作能力，TV Show
则是项目发布快照的公开发现面。低频账户、团队、计费和凭据保持全局可达，
但不与高频创作对象混在同一层级。

## 已观察发现

- 首页不是传统营销落地页，而是发现、输入和启动创作的工作台。
- Web 中存在项目/画布层级，CLI 中 workspace/project 用词与 Web 需要继续对照。
- 工作流与故事板是同一画布中的两个视图；公开样例展示图与媒体投影。
- Agent 已在首页和画布侧栏出现；是否存在独立页面及其共享规则待确认。
- Skill、模型和资产同时出现在首页、Agent 和节点内，应由统一目录与权限规则
  驱动，而不是各页面维护各自列表。
- 积分、个人中心、订阅/购买记录和资产从 LibTV 新开 LiblibAI 主站页面，并共享
  登录态；它们是跨产品账户域，不是 LibTV 内部孤立页面。
- 共享资产页按 Lib 生成器、LibTV、ComfyUI、WebUI 和 AI 应用标记来源，证明
  多种创作表面复用同一资产信息架构。

## 目标设计推断

- Project 建议作为权限/资源边界，Canvas 作为编辑边界，Node 作为执行单元。
- TV Show 建议展示冻结的公开快照；复制应创建私有副本而非授予源项目写权限。

## 待确认

- Workspace 与团队在 Web 端是否是同一切换器、是否存在独立管理页。
- Agent 独立页与项目侧栏会话的 URL、生命周期和共享规则。
- 项目、画布和发布快照的稳定 URL 及版本标识。
- 团队角色、发布审核、模型可见性和资产共享的完整权限矩阵。
- 登录后复制公开项目时的目标 workspace 选择、素材复制策略和失败恢复。
